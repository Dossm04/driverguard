# DriverGuard — Полная сборка софта в Claude Code
### Установка → CLAUDE.md → 16 шагов с готовыми промптами

**Принцип:** один шаг = одна сессия Claude Code. Каждый шаг заканчивается проверкой «Готово, когда…» — не переходите дальше, пока пункты не выполнены. Визуал берём из ваших Figma-скриншотов, логику — из HTML-прототипа дашборда. Темы день/ночь — обязательное требование каждой страницы.

---

## 0. Почему Claude Code, а не Cowork

Cowork — инструмент для документов, исследований, работы с файлами. Claude Code — агент внутри репозитория: сам создаёт структуру проекта, ставит зависимости, запускает `npm run dev` и `pytest`, читает ошибки в терминале и чинит их, делает git-коммиты, читает ваши скриншоты дизайна. Для сборки фронтенда + бэкенда + PWA + софта устройства нужен именно он.

## 1. Установка и старт (10 минут)

1. **Установка.** macOS / Linux / WSL: `curl -fsSL https://claude.ai/install.sh | bash`. Windows: через WinGet или PowerShell-команду из официальной документации (code.claude.com/docs). Либо просто **Claude Desktop → вкладка Code → New session → выбрать папку проекта**. Нужен платный план (Pro/Max/Team) — бесплатный Claude Code не включает.
2. **Папка проекта.** Создайте `driverguard/`, внутри `reference/` и положите туда: два PNG-скриншота из Figma (`figma_overview_top.png`, `figma_overview_bottom.png` — переименуйте как удобно), `driverguard_dashboard.html`, `driverguard_demo.html`, `DriverGuard_MVP_Полный_план.md`, `DriverGuard_обучение_моделей_старт.md`, `DriverGuard_Figma_промпты.md`. Claude Code умеет читать изображения — это и обеспечит верность дизайну.
3. **`git init`** в папке, затем создайте файл `CLAUDE.md` (раздел 2).
4. Запустите `claude` в папке (или сессию в Desktop) и вставляйте промпты из раздела 4 по порядку.

## 2. CLAUDE.md — скопировать в корень проекта целиком

```markdown
# DriverGuard — контекст проекта

## Что это
Edge-AI система мониторинга усталости водителей грузовиков (Казахстан). Камера в кабине
(позже Raspberry Pi 5 + Hailo) ловит микросон/отвлечение/телефон/курение/ремень, работает
офлайн, при появлении сети шлёт события в облако. Облако: дашборд координатора, лидерборд,
чек-листы с ИИ, PWA водителя, Telegram-алерты. Язык интерфейса — русский.

## Монорепо
- backend/  — FastAPI, SQLAlchemy 2, Alembic, PostgreSQL, MinIO(S3), WebSocket, pytest
- web/      — Next.js 14 (App Router), TypeScript, Tailwind, shadcn/ui, lucide-react,
              recharts, react-leaflet, next-themes, TanStack Query. Роуты: /(admin)/* и /driver/*
- device/   — Python 3.11: MediaPipe DMS, машина состояний, SQLite-очередь, sync-агент,
              режим --source 0 (вебкамера) и --simulate (без камеры)
- bot/      — aiogram 3, алерты координатору
- ml/       — скрипты обучения YOLOv8 (Colab-совместимые)
- infra/    — docker-compose.yml (db, minio, backend, web, bot), .env.example
- reference/ — ЭТАЛОНЫ: figma_*.png (визуал), driverguard_dashboard.html (логика, демо-данные),
              документы плана. Перед работой над UI открывай PNG.

## Дизайн-система (строго через CSS-переменные, никаких hardcoded-цветов)
Тёмная (по умолчанию, как в Figma): --bg #0F1523, --sidebar #0C1120, --card #151C2E,
--card-hover #1A2338, --border #1F2A3F, --text #E6EBF5, --muted #8B98B3,
--accent #3B82F6, --ok #22C55E, --warn #F59E0B, --danger #EF4444, --offline #64748B.
Светлая: --bg #F4F6FB, --sidebar #FFFFFF, --card #FFFFFF, --card-hover #F8FAFF,
--border #E4E9F2, --text #0F172A, --muted #64748B, --accent #2563EB, --ok #16A34A,
--warn #D97706, --danger #DC2626, --offline #94A3B8.
Шрифт Inter, радиусы карточек 16px, кнопок 12px, иконки lucide 20px. Статус-пилюли —
тонированный фон (цвет 15% прозрачности) + цветной текст. Красный только для критического.
Цифры — tabular-nums.

## Обязательные правила
1. Каждая страница и компонент работают в ОБЕИХ темах (переключатель в топбаре + в
   Настройках, сохранение в localStorage, учёт prefers-color-scheme). Графики и карта
   тоже переключаются (карта: CARTO dark_all / light_all).
2. Сайдбар и топбар — как в reference/figma_*.png: логотип «DriverGuard / Fleet Safety»,
   пункты Обзор, Live-карта, События(бейдж), Лидерборд, Водители, Чек-листы, Отчёты,
   Настройки; внизу виджет «Устройств онлайн 5/6» с сегментами. Топбар: заголовок,
   поиск, сегмент-переключатель «Сегодня | 7 дней | 30 дней», колокольчик с бейджем,
   аватар «Айгерим · Координатор», переключатель темы.
3. Демо-данные (seed) должны давать ровно картинку Figma: 5/6 машин, 14 событий сегодня
   (+3 к вчера), 3 критических за 24ч, средний Score 78 (цель ≥80), 12 480 км/нед,
   аптайм 98.2%, 3 водителя в красной зоне (Score <60).
4. Типы событий: microsleep «Засыпание за рулём», distraction «Отвлечение >N сек»,
   phone «Телефон за рулём», smoking «Курение», seatbelt «Ремень не пристёгнут»,
   speeding «Превышение скорости +N км/ч», fatigue «Усталость (PERCLOS)»,
   head_nod «Клевок головой», camera_sabotage «Саботаж камеры», harsh_braking
   «Резкое торможение», sos «SOS». severity: critical / warning / info.
5. Скоринг: Score = clamp(40..100, 100 − Σ(вес × модификатор_скорости) × 7/дней × 0.8
   + бонус_серии(≤10)). Веса: microsleep 15, camera_sabotage 20, phone 10, distraction 4,
   seatbelt 6, head_nod 5, smoking 4, speeding 3 (+1 за каждые 10 км/ч сверх 20),
   harsh_braking 2, fatigue 2. Модификатор: phone/microsleep при >60 км/ч ×1.5;
   phone при <5 км/ч ×0.3. Учитываются только события status ∈ {new, confirmed};
   «false_positive» возвращает баллы. Пороги и веса редактируются в Настройках.
6. После каждого шага: запусти линтер и тесты, подними dev-сервер, проверь, что страница
   открывается без ошибок в консоли, сделай git commit с осмысленным сообщением.
7. Все тексты UI — русский. Формат номера машины «KZ 4521 AB», ФИО «Иванов А.С.».
8. Ошибки не скрывать: если что-то не работает — сказать прямо и предложить фикс.

## Команды
- infra: `docker compose -f infra/docker-compose.yml up -d`
- backend: `cd backend && uvicorn app.main:app --reload` · тесты `pytest -q`
- web: `cd web && npm run dev` · `npm run lint` · `npm run build`
- device: `cd device && python -m dg --simulate` / `--source 0`
- seed: `cd backend && python -m app.seed`

## Не делать
- Не использовать localStorage/sessionStorage для данных приложения (только тема и токен).
- Не тащить тяжёлые UI-киты кроме shadcn. Не писать цвета хардкодом. Не пропускать тесты.
- Не выдумывать эндпоинты на фронте — только те, что есть в backend/openapi.
- Не менять формулу скоринга без обновления этого файла.
```

## 3. Правила работы (чтобы Claude Code не «уплыл»)

- В начале большого шага просите план: «Сначала составь план файлов и действий, дождись моего ОК, потом пиши код».
- Между шагами используйте `/clear` (сброс контекста) — CLAUDE.md подгружается заново автоматически.
- Ошибка в терминале или браузере → просто вставьте её текст, Claude Code починит.
- Каждый раз, когда Claude Code сделал не так, а вы поправили, — добавьте правило в CLAUDE.md. Это совет создателя Claude Code, и он реально работает: файл накапливает знания о проекте.
- В конце шага: `git commit`. Если что-то сломалось безнадёжно — `git checkout .` и повтор шага.
- Держите CLAUDE.md коротким (около 100 строк); детали кладите в `docs/` и ссылайтесь.
