# DriverGuard Android 0.7 — рабочее пространство водителя

Нативный APK для Android 8+, arm64 (Samsung A53) и x86_64. Главный экран объединяет аккаунт, предрейсовый аудит, рейс, мониторинг и журнал. Точность на A53, в движении и ночью требует отдельного испытания.

## Первый запуск

1. Установить `DriverGuard-A53-v07.apk` поверх прежнего DriverGuard, не удаляя приложение. Подпись должна совпадать для обновления.
2. Открыть **Профиль**, указать адрес HTTPS-сервера (можно с `/api/v1`), номер и PIN водителя. Первый вход требует сети. Для локального стенда разрешён HTTP с частным IPv4. `localhost` на телефоне означает сам телефон.
3. Войти и загрузить шаблон аудита. PIN не сохраняется; токены зашифрованы Android Keystore. Профиль кэшируется.
4. **Аудит**: обязательные ответы → фотографии → итог → отправка. Без сети сохраняется очередь, а не разрешение на выезд.
5. **Смена → Открыть мониторинг → Начать наблюдение**. Разрешить камеру и проверить мультимедийную громкость. Лицо целиком в кадре; первые три секунды смотреть прямо для настройки положения головы.

Сервер должен быть обновлён командой `alembic upgrade head`, включая миграции `e5f6a7b8c9d0` и `f6a7b8c9d0e1`. Приложение проверяет `/checklists/mobile-capabilities` для аудита и `/drivers/me/camera-capabilities` для измерений: старый backend не должен незаметно потерять новые поля. До обновления очередь сохраняется на телефоне.

## Сценарий водителя

Вход → аудит автомобиля → решение координатора → рейс → мониторинг → перерыв → завершение рейса. Камера отдельно доступна без аккаунта; события такого сеанса остаются локальными и не присваиваются позднее другому водителю.

Анкета и фото-слоты загружаются из настроек компании. Черновик сохраняется автоматически, фотографии сжимаются до1600px JPEG без метаданных. Очередь принадлежит исходному аккаунту и серверу. UUID защищает от дубликатов при повторной отправке. Подтверждённый отказ сервера можно исправить; при неопределённом исходе запрос повторяется с прежним UUID.

Вход, передача данных, рейс, SOS и решение координатора требуют связи с сервером. Без настроенного AI-провайдера фотографии ожидают ручной проверки — успешный анализ не имитируется. Назначенные уроки видны в профиле; просмотр учебного материала открывает веб-кабинет с отдельным входом.

## Без интернета

- Камера, встроенная FaceLandmarker и локальные правила работают на телефоне.
- Наблюдения сохраняются в SQLite с первоначальным временем и UUID.
- Ранее загруженный аудит можно заполнить, снять фото и поставить в очередь.
- Профиль и локальный журнал остаются доступны.
- Опциональная запись видео не требует сети.

Приложение должно оставаться открытым. Сворачивание/блокировка останавливает мониторинг. Фоновой круглосуточной службы нет. Главная страница проверяет очередь каждые30секунд, мониторинг — каждые15секунд. Ошибка сети сохраняет очередь. Смена аккаунта или адреса не переносит прежние записи другому водителю.

## Модель и сигналы

MediaPipe FaceLandmarker — предобученная модель лица. DriverGuard применяет временные правила; это не собственная обученная классификация сна.

| Наблюдение | Правило прототипа | Результат |
|---|---|---|
| Закрытые глаза | 1,5 с; оба eyeBlink ≥0,55 или EAR <55% персональной базы; открытие подтверждается 200 мс | Одно событие за эпизод; звук повторяется каждые 0,9 с |
| Персональная калибровка | 3 с стабильного наблюдения с открытыми глазами | База EAR, положения и поворота головы; ручной повтор в настройках |
| Моргания | Наблюдаемые эпизоды 60–500 мс за 60 с | Счётчик на экране и в измерениях; короткие моргания могут пропускаться при недостаточной частоте кадров |
| PERCLOS | ≥20% за окно60с, ≥15с наблюдений и80% покрытия | Предупреждение не чаще раза в30с |
| Возможный зевок | Рот открыт≥1,2с | Локальный счётчик; речь тоже может открывать рот |
| Повторные зевки | ≥3эпизодов за10мин | `fatigue` и короткий сигнал |
| Наклон головы | Исходная разница глубины точек chin/forehead >0,13 от базы, 2 с | `head_nod` и короткий сигнал; это относительная величина, не градусы |
| Поворот головы | Относительный yaw >0,35 и свежая GPS-скорость >20 км/ч непрерывно 8/15 с | `distraction`: warning/critical; критическая тревога повторяется |
| Превышение лимита | Свежая GPS-скорость выше выбранных 60/90 км/ч в течение 10 с | `speeding`, величина превышения; повтор не чаще 60 с |
| Нет лица | 3 с — локальное предупреждение; 5 минут непрерывно при GPS >5 км/ч — событие | `camera_sabotage` требует проверки причины, а не утверждает умышленное действие |
| Нет свежих кадров | Нельзя достоверно наблюдать | Таймеры эпизодов и повтор тревоги сбрасываются |

«Без звука на30секунд» временно отключает звук, сохраняя распознавание и журнал. Тест громкости не создаёт событие. UI показывает нулевую громкость отдельно.

GPS включается отдельно в дополнительных настройках с точным разрешением Android и работает только при открытом мониторинге. Не используются устаревшие или имитированные позиции. Принимаются измерения не старше 5 с с точностью позиции ≤30 м и скорости ≤3 м/с. Потеря подходящего сигнала отключает зависящие от движения события; нулевая скорость не подставляется. Лимит 60/90 выбирает пользователь, это не распознавание дорожных знаков.

Каждое отправляемое событие содержит первоначальное время, UUID, источник Android, версию правил и фактические измерения: закрытие глаз, EAR/базу, моргания, PERCLOS/покрытие окна, возможные зевки, положение головы. При наличии точного GPS передаются координаты и скорость. Измерения сохраняются в локальной очереди и в облачной карточке события. Blendshape не является калиброванной вероятностью сна; соответствующая уверенность в панели обозначается как некалиброванная.

Модели ремня и сигареты находятся в дополнительных настройках, выключены по умолчанию и не отправляют подтверждённые нарушения. Собственная четырёхклассовая модель из Colab пока не имеет подтверждённого результата обучения. Телефон у уха в APK не реализован. Для этого нужны готовые веса, независимая проверка и интеграция, а не только включение опции.

## Хранение

- Видео: сегменты до30с/32МБ, до2ГБ и48часов; очистка при работе приложения. Автоматической отправки видео нет.
- Фото аудита: подтверждённые сервером локальные копии очищаются после7дней или при превышении256МБ, при открытии аудита. Неотправленные фото защищены.
- Локальные и отправленные события старше 30 дней очищаются при добавлении новых. Ожидающие отправки защищены. При 50000 записях сохранение останавливается с видимой ошибкой.
- Отменённые/неудачные фотографии и бесхозные временные файлы очищаются; файлы сохранённых осмотров и незавершённой съёмки защищены.
- Журнал и CSV ограничены текущим аккаунтом. Локальный режим показывает локальные записи.

## Проверка на A53

1. Отключить сеть и запустить камеру: модель открывается без скачивания.
2. Проверить10обычных морганий и5закрытий глаз по4–5секунд: сигнал повторяется, один эпизод даёт одно событие.
3. Открыть глаза: звук прекращается. Закрыть камеру рукой: показано отсутствие наблюдения.
4. Проверить выключение звука и возвращение через30секунд.
5. Проверить3раздельных открытия рта по1,5–2секунды с паузами; проверить обычную речь на ложные срабатывания.
6. Войти, отключить сеть, создать событие и аудит, вернуть связь. Убедиться, что они появились в панели нужного водителя.
7. Перезапустить приложение: журнал, черновик и аккаунт сохраняются; камеру нужно запустить заново.
8. Проверить30–60минут работы, температуру, заряд, задержки. Это не заменяется сборкой и модульными тестами.

11 октября пользователь подтвердил на A53 повторяющуюся тревогу до открытия глаз в версии 0.5. Для 0.6 этот сценарий нужно повторить после добавления EAR; GPS и новые критерии пока подтверждены тестами кода, а не дорожным испытанием. Не проверяйте опасные состояния самостоятельно за рулём.

## Соответствие исходной идее

Пороги сверены с DEV-3—DEV-14 исходного ТЗ в `reference/DriverGuard_#U0422#U0417_v1.0.md` и `device/dg/config.py`. Из рабочего звукового сценария сохранён порог двух eyeBlink ≥0,55 и добавлен исходный EAR-fallback; это осознанное отличие от первоначального 0,5 среднего eyeBlink. Покрытие окна PERCLOS дополнительно проверяется, чтобы пропуски кадров не считались закрытыми глазами.

Исходный план отдельного устройства также включал ИК-камеру, OBD, фоновую службу, голосовые профили, дистанционную конфигурацию, кольцевые клипы 10 с до/5 с после и их облачную отправку. В текущем APK эти пункты не считаются готовыми. Запись видео — отдельная локальная опция; обычная камера A53 не обеспечивает ИК-наблюдение в полной темноте. Наличие APK и сервера не подтверждает завершённое обучение предметных моделей или точность в реальном автопарке.

## Сборка

JDK17, Android SDK35/build-tools35.0.0, Gradle8.11.1. SDK-лицензии принимает владелец среды. Укажите `sdk.dir` в локальном `local.properties` или `ANDROID_HOME`.

```sh
python fetch_models.py
gradle --no-daemon testDebugUnitTest assembleDebug lintDebug
```

Модели проверяются по SHA-256 из `models.json` до сборки. APK лежит в `app/build/outputs/apk/debug/`; Samsung использует arm64-v8a. Debug-подпись предназначена для стенда; сохраняйте исходный ключ для обновлений.

Происхождение и условия весов: `models.json`, `THIRD_PARTY_NOTICES.md`. Исследовательские веса имеют отдельные условия распространения. Сервер: `../docs/deploy-railway.md`. GitHub хранит код, а FastAPI/PostgreSQL запускаются на хостинге.

## Дополнения 0.7 — 13 октября 2026

Вход показывает отдельное окно ошибки и состояние рядом с кнопкой. Номер нормализуется (пробелы/скобки/8→+7), PIN проверяется до запроса. Шаблон аудита загружается на экране аудита и больше не задерживает переход после входа. Кнопка восстановления адреса возвращает действующий API.

В «Профиле» доступны шесть встроенных уроков, короткий вопрос и сохранение чтения без сети. Назначенные уроки связаны с ID назначения, исходным аккаунтом и сервером; их прохождение отправляется отдельной очередью. Самостоятельное чтение не выдаётся за выполненное назначение. Новая миграция a8b9c0d1e2f3 добавляет только три отсутствующих элемента каталога, не создаёт событий, назначений или результатов и не меняет существующие уроки.

Источники общих рекомендаций: [NHTSA — сонливость](https://www.nhtsa.gov/risky-driving/drowsy-driving), [отвлечение](https://www.nhtsa.gov/campaign/distracted-driving), [ремни](https://www.nhtsa.gov/vehicle-safety/seat-belts). Это информационные материалы, не подтверждение пригодности к рейсу.

CSV теперь содержит value и полный metadata_json с измерениями/GPS, с корректным экранированием. Новые типы событий имеют русские названия. В профиле есть готовность камеры/громкости/памяти и состояние очереди. Настройка записи видео сохраняется; лимит увеличен до2ГБ, перед новым сегментом требуется минимум512МБ свободного места. Хранение по возрасту остаётся48часов.

На 13 октября серверный вход по действующему номеру/PIN проходит. Пользователь сообщил, что кнопка входа на A53 не даёт понятного результата; новая версия устраняет невидимое сообщение, но точная причина входа на физическом телефоне требует повторной проверки. Установка APK и тесты кода не заменяют этот шаг.
