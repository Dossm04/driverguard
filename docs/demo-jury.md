# Стенд для жюри: 30–40 человек с телефонами одновременно

Сценарий: жюри получает учётки, каждый со своего телефона входит в PWA, включает камеру
(DMS в браузере), их события появляются на Live-карте и в «Событиях» у координаторов;
несколько наблюдателей-администраторов одновременно работают в панели — как на `localhost:3000`.

## Проверка готовности одной командой

Запускать дважды: за час до показа и ещё раз за десять минут.

```bash
make preflight PASS='<новый пароль админа>' N=40
```

Скрипт ничего не меняет. Он проверяет живой контур, по которому пойдут
телефоны судей: вход по PIN, регистрацию на карте, приём события DMS. Плюс
пароли по умолчанию, секреты в `infra/.env`, свежесть резервной копии,
учётки жюри, chat_id бота, место на диске.

На каждую проблему печатается готовая команда исправления, а в конце —
вердикт «готово» или «не готово» со списком блокирующих замечаний.

После `make tunnel` повторите проверку по публичному адресу — камера
в браузере работает только по HTTPS:

```bash
make preflight API=https://<адрес>/api/v1 WEB=https://<адрес> PASS='<пароль>' N=40
```

Скрипт добавляет в ленту одно проверочное событие «засыпание».
Пометьте его ложным перед показом, чтобы не смущало жюри.

## За день до показа

```bash
git pull
make secrets-check FIX=1        # случайные JWT_SECRET / MINIO_ROOT_PASSWORD в infra/.env (DG_SECRET — см. ниже)
make demo                       # стек в Docker (db, minio, backend, web, bot, симулятор)
make backup                     # копия базы и фото «до» (backups/<дата>)
make load-test N=40 ADMINS=5 DURATION=60   # репетиция нагрузки: должно быть «ИТОГ … OK»
```

**Пароли по умолчанию.** Через публичную ссылку `admin123`, PIN `1234` и `device-secret-1`
знает любой, кто видел репозиторий, поэтому `make tunnel` откажется открывать туннель, пока они
действуют. Смените до показа:

- admin: Настройки → Пользователи → `admin@driverguard.kz` → новый пароль (или `ADMIN_PASSWORD`
  в `infra/.env` до первого `make demo`);
- PIN шести демо-водителей: Водители → карточка → PIN (или `DRIVER_PIN` в `.env` до seed);
- секрет устройства DG-0001 (`device-secret-1` из seed): на свежем стенде `make demo` сам ставит
  случайный `DG_SECRET` до первого seed; если база уже засеяна — Настройки → Устройства → DG-0001 →
  отключить, либо `python infra/secrets_check.py --fix --with-device` и пересеять
  (`SEED=always make demo`, демо-данные сбрасываются к эталону). Туннель при этом только
  предупреждает, а admin/PIN по умолчанию — блокирует.

Demo-подсказки с паролями на экранах входа в production-сборке скрыты (показать сознательно:
`NEXT_PUBLIC_DEMO_HINTS=1`).

Проверьте ноутбук: питание от сети, режим сна выключен, Docker Desktop с 4+ ГБ памяти,
Wi-Fi/4G с исходящим доступом (туннель). Ключ ИИ: `make ai-setup KEY=…` (Настройки →
Чек-лист → «Проверить ИИ» должно отвечать).

### Windows без `make` (PowerShell)

Те же шаги прямыми командами — скрипты выполняются внутри контейнера backend, ничего
ставить на ноутбук не нужно (кроме Docker Desktop и `cloudflared`):

```powershell
$C = "docker compose -f infra/docker-compose.yml"
Invoke-Expression "$C --profile full up -d --build"                      # = make demo
python infra\backup.py create --keep 10                                    # = make backup
Invoke-Expression "$C exec backend python scripts/load_test.py --drivers 40 --admins 5 --duration 60"   # = make load-test
Invoke-Expression "$C exec backend python scripts/mentors.py --count 40 --out /tmp/mentors.csv"         # = make mentors N=40
Invoke-Expression "$C cp backend:/tmp/mentors.csv .\mentors.csv"           # файл с паролями на ноутбук (не коммитить)
python infra\tunnel.py                                                     # = make tunnel
python infra\ai_setup.py --key sk-…                                        # = make ai-setup KEY=…
```

`python` — Python 3.11+ из python.org или Microsoft Store (для `backup.py`/`tunnel.py` нужен только
стандартный набор). Восстановление: `python infra\backup.py restore backups\<дата>`.

## За час до показа

```bash
make mentors N=40 ROLE=viewer   # 40 комплектов: наблюдатель панели (только чтение) + водитель PWA + машина
                                # ROLE=coordinator — только 2–3 ведущим (review событий, правки водителей)
                                # пароли и PIN печатаются ОДИН раз → make mentors N=40 --out mentors.csv
make tunnel                     # публичные HTTPS-ссылки; пересборка web ≈ 2–3 мин
```

`make tunnel` открывает три туннеля (панель, API, MinIO — иначе фото чек-листов по
presigned-ссылкам на `localhost:9000` у удалённых участников не откроются), включает
`TRUST_PROXY=true` (лимиты по реальному IP за Cloudflare) и `NEXT_PUBLIC_MP_WASM_URL`
(WASM MediaPipe с CDN jsdelivr, версия из package-lock: 40 телефонов не качают по 10 МБ с
ноутбука через туннель), перезапускает backend, web и бота. При Ctrl+C всё возвращается к
локальным адресам. Перед туннелем уберите учётки нагрузочного теста, если они остались после
прерванного прогона: `docker compose -f infra/docker-compose.yml exec backend python
scripts/load_test.py --remove`.

**Не запускайте `npx playwright test` на демо-ноутбуке**: e2e перед прогоном пересеивает базу
(стирает учётки жюри и их события); против не-localhost адреса скрипт откажется сам.

Раздайте каждому члену жюри карточку (из `mentors.csv`): ссылка `<панель>/driver`, телефон
`+7 777 000 00NN`, PIN; для роли наблюдателя — `<панель>/login`, `mentorNN@demo.driverguard.kz`,
пароль. Администраторам-наблюдателям — `admin@driverguard.kz` (пароль смените заранее в
Настройки → Пользователи) или их собственные учётки роли admin/coordinator.

Ссылки короткие: сгенерируйте QR на `<панель>/driver` (любой QR-генератор) и покажите на экране.

## Во время показа

1. Жюри: `<панель>/driver` → вход по телефону и PIN → вкладка **Камера** → «Разрешить камеру»
   (HTTPS через туннель это позволяет; iOS Safari — только в Safari, не в приложении Telegram).
2. Через 5–10 с телефон становится «онлайн»: Настройки → Устройства (`WEB-M0NN`), Live-карта
   (машина ментора стоит там, где телефон), Настройки → Пользователи → «Онлайн».
3. Пусть закроют глаза на 2–3 с — событие «Засыпание за рулём» появляется в «Событиях» и в
   Telegram у координатора; отвернуться на 8 с — «Отвлечение». Включите «Имитация 60» и
   поднесите ладонь к уху на 2 с — «Телефон за рулём» (critical, сирена); подержите пальцы у
   рта 3 с или трижды «затянитесь» за минуту — «Курение». Ремень с телефона не определяется
   (нужен обученный YOLO-детектор из ml/).
4. Чек-лист с фото — 7 ракурсов, ИИ-вердикт за 10–30 с (alem.ai, Gemma 4).
5. Наблюдатели в панели: Обзор, События (review без перезагрузки), Лидерборд, профиль водителя.

Где смотреть, что стенд жив: `<API>/api/v1/health/ready` (JSON `ready`), Настройки →
Пользователи (кто онлайн), а для админа — `<API>/api/v1/health/metrics` (p95 по маршрутам,
пул БД, число WS-соединений; открыть с токеном через Swagger `<API>/docs` → Authorize).

## Ёмкость и лимиты (что проверено)

- Нагрузочный тест `make load-test N=40 ADMINS=5 DURATION=60`: 40 телефонов (heartbeat 15 с,
  событие раз в ~20 с, профиль 30 с) + 5 панелей (WebSocket + опрос как в TanStack Query).
  Порог «OK»: ошибок ≤0.5%, p95 ≤1 с. Репетиция в облачной песочнице (2 vCPU, слабее
  ноутбука): 40 телефонов + 5 панелей — 0 ошибок, p95 287 мс (вход ~290 мс из-за bcrypt,
  остальные маршруты ≤100 мс); двойной запас 80 телефонов + 10 панелей — 0 ошибок,
  p95 731 мс, 4 800 WS-сообщений за минуту, пул БД без переполнения.
- Лимиты backend: 120 НЕУДАЧНЫХ входов/мин с одного IP (успешные входы зала не считаются),
  1200 запросов/мин на пользователя (ключ — подписанный токен, подделать нельзя), тело JSON
  ≤2 МБ, чек-лист ≤80 МБ; пул БД 20+30, пул потоков 100. Поднять: `RATE_LIMIT_AUTH_PER_MIN=300`
  в `infra/.env` → `docker compose -f infra/docker-compose.yml --profile full up -d backend`.
- Быстрые туннели Cloudflare (`trycloudflare.com`) без гарантий пропускной способности:
  ~1–2 МБ/с на поток. Поэтому WASM/модель — с CDN, фото чек-листа сжимаются на телефоне.
  Если туннель «тормозит» — второй план ниже.
- Камера в браузере: MediaPipe на телефоне ~10–20 FPS; старые Android (< 2019) могут греться —
  это нагрузка телефона, не сервера.

## План Б (если что-то упало во время показа)

| Симптом | Действие |
|---|---|
| Панель не открывается по ссылке туннеля | `make tunnel` перезапустить (адреса изменятся — заново раздать QR). Если сеть ноутбука пропала — раздать Wi-Fi с телефона, туннель поднимется сам |
| `/health/ready` → 503 | `docker compose -f infra/docker-compose.yml ps` — какой контейнер unhealthy; `docker compose … restart db minio backend`; данные не теряются (volumes) |
| Много 429 при входе | Лимит считает только НЕУДАЧНЫЕ входы с одного IP (120/мин): значит, кто-то перебирает пароли. Учётка после 5 ошибок ждёт 1→2→4…60 с, не 15 минут. Поднять порог: `RATE_LIMIT_AUTH_PER_MIN=300` в `infra/.env`, `docker compose … up -d backend` |
| Камера не запрашивает разрешение | Только HTTPS (ссылка туннеля, не `http://IP`); в iOS открыть в Safari; проверить, что сайт не в списке заблокированных камер |
| ИИ не отвечает | Чек-лист сохраняется с вердиктом «ИИ недоступен» — показ продолжается; Настройки → Чек-лист → «Проверить ИИ»; `make ai-setup KEY=…` |
| Вся база «испорчена» демонстрациями | `make backup-restore DIR=backups/<дата-до-показа>` — 1 минута |
| Ноутбук перезагрузился | `make demo` → `make tunnel` (новые ссылки) → учётки менторов сохранились в базе |

Без интернета вообще: стенд работает в локальной Wi-Fi по `http://<IP-ноутбука>:3000`, но
камера в браузере телефона требует HTTPS — тогда DMS показывать с ноутбука
(`make device-camera`, веб-камера) и симулятором (`device-sim`), а телефоны используют
чек-лист и Score.

## «Железный» режим: бортовое устройство на ноутбуке, результат на телефоне

Тот же софт, что поедет на Raspberry Pi 5, запускается на ноутбуке с веб-камерой и работает как
устройство DG-0001 из seed: события уходят в панель и на карту, а жюри видит их на своих
телефонах в панели или в PWA водителя Иванова А.С. (`+77012441832`).

```bash
cd device && python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"   # один раз
make device-camera            # окно с HUD: лицо, EAR, PERCLOS, жесты рук; q — выход
```

Windows: `cd device; py -3.11 -m venv .venv; .venv\Scripts\pip install -e ".[dev]";
.venv\Scripts\python -m dg --source 0 --display --gps sim`. Секрет устройства берётся из
`device/config.yaml` (`device-secret-1`, или значение `DG_SECRET` из `infra/.env`, если вы
пересеяли базу с новым секретом). Первый запуск скачивает модели MediaPipe (~12 МБ).
Что показать: закрыть глаза (сирена через 1,5 с), ладонь к уху (телефон), пальцы ко рту
(курение), закрыть камеру рукой (через 5 мин в движении — саботаж). Без камеры — симулятор
`make device-sim` (события по расписанию). ONNX-детектор телефона/сигареты/ремня включается
автоматически, когда в `device/models/` появится обученная модель (`ml/scripts/registry.py promote`).

## После показа

```bash
make backup                                      # копия «после»
cd backend && .venv/bin/python scripts/mentors.py --remove   # убрать учётки жюри
```

Ротация секретов: ключ alem.ai (кабинет alem.ai → новый ключ → `make ai-setup KEY=…`), токен
бота (BotFather → `/revoke`), `JWT_SECRET` в `infra/.env` (все выйдут из системы — нормально).
