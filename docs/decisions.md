# Журнал решений

Формат: дата · решение · причина. Неоднозначности из ТЗ решаем простейшим вариантом и фиксируем здесь.

## 2026-09-17 — Пакет 10: баги со стенда и телефон/курение без обученной модели

- **Анкета чек-листа на KZ/EN.** Кнопки «Иә/Жоқ» отправляли переведённый текст как значение,
  backend ждёт «да/нет/н-п» — значение теперь всегда русское, переводится только подпись.
- **«Хранилище фото временно недоступно» при добавлении водителя.** Presigned-ссылка для браузера
  подписывается через клиент с публичным адресом MinIO (`localhost:9000`), а minio-py перед
  подписью ходил за регионом бакета на этот адрес — из контейнера backend он недоступен. Регион
  задан явно (`MINIO_REGION=us-east-1`), сетевого вызова больше нет.
- **Камера «не удалось загрузить модель».** Причина теперь печатается под сообщением (имя
  ошибки и шаг: js/wasm/model), а модели Face/Hand Landmarker Docker-сборка скачивает в
  `public/models` — страница берёт копию со своего сервера и не зависит от Google Storage
  (в локальной сети без интернета камера тоже работает).
- **Телефон и курение — по точкам руки, а не по YOLO.** Обученной модели (ml/) пока нет, а
  показать эти события с телефона и ноутбука нужно. MediaPipe Hand Landmarker (7,5 МБ, каждый
  третий кадр) даёт 21 точку руки; «ладонь у уха» = телефон (≥2 с при движении, critical),
  «кончик пальца у рта» = сигарета (3 с подряд или 3 затяжки за минуту, warning). Расстояния
  нормируются на ширину лица. Одна математика в `web/lib/dms/gestures.ts` и `device/dg/gestures.py`;
  на устройстве жест и ONNX-детектор объединяются по максимуму confidence, `DG_GESTURES=off`
  отключает. Ограничение честно записано: жест не отличит телефон от чашки у уха — точность ниже
  YOLO, поэтому в ml/ остаётся задача обучить детектор phone/cigarette/seatbelt (датасет и
  пайплайн готовы), а **ремень** до обученной модели не определяется ни телефоном, ни устройством.
- **Backend принимает `phone` и `smoking` от PWA** (`CameraEventType`), `seatbelt` — по-прежнему
  только с устройства.

## 2026-09-16 — Пакет 9d: проверочные проходы (security-review и bug hunt независимыми агентами)

- **Ключ лимитера — только подписанный токен.** Первая версия брала хвост заголовка
  `Authorization` без проверки подписи: случайный `Bearer …` обходил любой лимит и раздувал
  словарь ключей. Теперь ключ — `sub` из JWT с проверкой HMAC (дёшево), иначе IP; ключей ≤20 000.
- **Лимит входа считает только неудачи.** 40 членов жюри за одним IP входят без риска 429;
  флуд неверными паролями по-прежнему режется. `/auth/device` добавлен в защищённые пути.
- **Блокировка учётки — прогрессивная пауза, не 15 минут.** Телефоны жюри предсказуемы
  (`+7777000NNNN`), и 5 чужих ошибок запирали бы человека на четверть часа; теперь после 5
  ошибок — 1, 2, 4 … 60 с между попытками (подбор ≤1/мин, жертва ждёт максимум минуту).
  bcrypt считается и для несуществующей учётки (время ответа не выдаёт email/телефон).
- **Слабый `JWT_SECRET` = отказ старта**, а не предупреждение: с `change-me` любой выписывает
  admin-токен. `make demo` и `make secrets-check FIX=1` (`infra/secrets_check.py`) генерируют
  JWT/MinIO/DG-секреты; compose требует `JWT_SECRET` явно. Тесты задают свой секрет в conftest.
- **Пароли по умолчанию не уезжают в публичный туннель.** `make tunnel` проверяет `admin123`,
  PIN `1234`, `device-secret-1` через API и отказывается открывать доступ (обход —
  `--allow-default-passwords`); seed читает `ADMIN_PASSWORD`/`DRIVER_PIN`, секреты DG-0002…0006
  случайные (`DG_SEED_KNOWN_SECRETS=1` — только тесты); демо-подсказки на экранах входа скрыты в
  production-сборке (`NEXT_PUBLIC_DEMO_HINTS=1` — показать сознательно).
- **Жюри — роль viewer.** `mentors.py --role viewer`: координатор мог сбрасывать PIN любому
  водителю и создавать события «за» других; наблюдатель только смотрит (телефоны маскируются).
- **Третий туннель — MinIO.** Фото чек-листов панель открывает presigned-ссылками прямо в MinIO;
  через туннель `localhost:9000` у удалённых участников не открывался — теперь
  `MINIO_PUBLIC_ENDPOINT` указывает на туннель MinIO. Бот тоже перезапускается (читает `WEB_URL`).
- **Тело запроса ограничено** (JSON 2 МБ, multipart 80 МБ, фото читается до 4 МБ + 1 байт,
  ≤10 доп. фото): водитель с 7×100 МБ мог уронить backend по памяти.
- **500 — из middleware, с CORS.** Обработчик Starlette живёт снаружи CORS, и браузер видел
  «CORS error» вместо «Внутренняя ошибка · request_id»; теперь JSON 500 шлёт сам middleware.
- **WebSocket: роль из базы, ≤6 соединений на пользователя, рассылка параллельная с таймаутом
  3 с** — удалённая учётка не держит карту, зависшая панель не тормозит остальных.
- **KPI аптайма и «машин на линии» считают только настоящие блоки** (`fw_version != web`):
  40 телефонов жюри шлют телеметрию лишь при открытой «Камере» и роняли аптайм до 10 %;
  демо-симулятор больше не «оживляет» телефоны после рестарта backend.
- **Гонка создания WEB-устройства** (первый heartbeat и первый батч одновременно) —
  `INSERT … ON CONFLICT DO NOTHING` по serial.
- **PWA «Камера»:** один батч в полёте, отправленные события убираются по uuid (терялись при
  медленном туннеле), ошибки данных 4xx не держат очередь; таймаут 45 с на WASM/модель с понятной
  ошибкой; `NotReadableError`/`OverconstrainedError`/`SecurityError` объясняются по-человечески;
  AudioContext создаётся в жесте пользователя (сирена на iOS); уход в фон ставит цикл на паузу и
  сбрасывает машину состояний (без ложного «саботажа» после возврата); heartbeat шлёт настоящий FPS.
- **Обновление токена — single-flight, разлогин только при отвергнутом refresh:** параллельные 401
  (профиль, heartbeat, очередь, WS) не устраивают шторм `/auth/refresh`, а 502/429 туннеля не
  выбрасывают 40 телефонов на экран входа посреди показа.
- **Service worker кэширует только `resp.ok`** (страница 502 от туннеля во время пересборки
  подменяла оболочку PWA навсегда); имя кэша `dg-shell-v2`.
- **«События» обновляются сами** (refetch 15 с): координатор на этой странице видел новые события
  только после F5.
- **E2E не пересеивает чужую базу:** seed перед прогоном разрешён только для localhost (иначе
  `E2E_ALLOW_SEED=1`); runbook предупреждает не запускать e2e на демо-ноутбуке.
- Отложено (задокументировано в ARCHITECTURE): отзыв отдельных токенов (jti), CSP, Swagger только
  для admin, привязка порта MinIO к 127.0.0.1 (LAN-режим без туннеля требует доступа телефонов),
  Redis для лимитеров при нескольких воркерах.

## 2026-09-16 — Пакеты 9b/9c: production-стандарты и стенд для жюри (30–40 телефонов)

- **Матрица стандартов — `docs/ARCHITECTURE.md`.** По чек-листу PRODUCTION_STANDARDS
  отмечено, что применено, что заложено/отложено и что неприменимо на масштабе пилота
  (один сервер). Базовые вещи разделов 4/5 (логи, метрики, заголовки, лимиты, секреты)
  сделаны без обсуждения; Kubernetes/брокеры/шардинг — осознанно нет.
- **Один ASGI-слой `ObservabilityMiddleware`** вместо нескольких библиотек: request-id,
  access-лог, метрики по шаблонам маршрутов, security-заголовки, rate limit. Всё в памяти
  процесса — при `uvicorn --workers > 1` или втором сервере лимитеры/метрики уезжают в
  Redis (записано в ARCHITECTURE как шаг перед пилотом). `slowapi`/Prometheus не тянем.
- **Rate limit по токену, вход — по IP, щедро.** Зал жюри сидит на одном Wi-Fi = один
  внешний IP, поэтому общий лимит считается на пользователя (последние 32 символа bearer),
  а лимит входа — 120/мин на IP (было 30: 40 человек с повторами упёрлись бы). Подбор
  пароля всё равно режется блокировкой учётки на 15 минут после 5 ошибок. За Cloudflare
  реальный IP берётся из `CF-Connecting-IP` только при `TRUST_PROXY=true` (`make tunnel`
  ставит сам) — иначе заголовок можно подделать.
- **CORS снаружи observability.** Порядок middleware выбран так, чтобы 429 лимитера и
  JSON-500 получали CORS-заголовки (иначе браузер показал бы «CORS error» вместо причины),
  а preflight OPTIONS не тратил лимит.
- **Healthcheck compose = `/health/ready`** (БД + MinIO), liveness `/health` остаётся
  без БД. Readiness отвечает 503 без деталей (детали в лог) — наружу не раскрываем, что
  именно упало. Метрики `/health/metrics` — только admin.
- **Пулы под 40 телефонов:** PostgreSQL 20+30 с `pre_ping`, пул потоков anyio 100
  (по умолчанию 40 — heartbeat 40 телефонов + панели вставали бы в очередь).
- **N+1 в списках водителей и устройств** (машина/депо по запросу на строку) найден
  нагрузочным тестом: при 86 водителях `GET /drivers` держал p50 1.6 с под нагрузкой,
  после `selectinload` — 0.42 с. Серия для профиля считается по одному водителю, а не по
  парку; клиент MinIO кэшируется (иначе каждая presigned-ссылка = GetBucketLocation).
- **Нагрузочный тест `scripts/load_test.py` / `make load-test`** повторяет реальный
  трафик PWA «Камера» (heartbeat 15 с, события, профиль 30 с) и панелей (WS + опрос как
  в TanStack Query); учётки создаёт и удаляет сам (`+77771…`, `@load.driverguard.kz`).
  Песочница (2 vCPU, без GPU): 40 телефонов + 5 панелей — 0 ошибок, p95 287 мс (вход с
  bcrypt ~290 мс, остальное ≤100 мс); 80 телефонов + 10 панелей, событие раз в 10 с —
  0 ошибок, p95 731 мс, 4 800 WS-сообщений за минуту, пул БД без overflow. Порог «OK»:
  ошибок ≤0.5 %, p95 ≤1 с.
- **Next 14.2 → 15.5 + React 19** ради 21 advisory (RCE в Image Optimization, cache
  poisoning): единственные правки — промис `params` в маршруте WASM, `useRef` с начальным
  значением, `react-leaflet` 5. Уязвимая копия `postcss` внутри next закрыта
  `overrides` (postcss ≥8.5.28); `npm audit` — 0. Next 16 не берём: `next lint` и часть
  API меняются, а выигрыша для стенда нет.
- **Бэкапы через контейнеры** (`infra/backup.py`): pg_dump/pg_restore из образа postgres,
  архив volume MinIO через alpine — работает на Windows без установки клиентов; копия
  проверяется сразу (`pg_restore --list`, `tar -t`). Восстановление останавливает backend
  и ждёт `/health/ready`.
- **CI без секретов:** GitHub Actions поднимает Postgres/MinIO сами, ключи ИИ не нужны
  (`AI_PROVIDER=mock`), e2e идёт поверх production-сборки web. Прогон в GitHub ещё не
  выполнялся (ветка без PR) — первый запуск покажет, что подправить в раннере.
- **E2E устойчивее к dev-серверу:** прогрев маршрутов в `globalSetup` (первый тест ловил
  таймаут на холодной компиляции), проверка service worker зависит от режима (`next dev`
  SW не регистрирует — проверяем отдачу `/sw.js`; `next start` — регистрацию).
- **Security-заголовки web без CSP.** CSP с MediaPipe (WASM с CDN, модель с Google
  Storage), тайлами OSM и inline-скриптами Next требует точной политики; черновик записан
  в ARCHITECTURE, включать после проверки на стенде, не за час до показа.

## 2026-09-15 — Правки после показа: пакеты 1–7 (сессии, чек-лист, ИИ, менторы, камера, языки)

- **Раздельные сессии и темы панели и PWA.** Токены `dg-token`/`dg-token-driver`, темы
  `theme`/`theme-driver`, язык `dg-lang`/`dg-lang-driver` — по области `/driver`, `/driver/*`
  (раздел панели `/drivers` — НЕ область PWA: проверка `isDriverPath`, а не `startsWith`).
  Так координатор и несколько водителей в одном браузере не выбивают друг друга.
- **Новичок без «100 % / 365 дней».** Серия ограничена стажем (`min(streak, tenure)`),
  водитель без событий в первую неделю — `is_new` («Новичок» вместо места, «Первая неделя»
  в PWA). Seed-водители созданы 400 дней назад, чтобы картинка Figma не менялась.
- **Шаблон чек-листа настраивается парком** (Настройки → Чек-лист): ключ `checklist` в
  settings хранит только отличия от каталога v2 (скрытые слоты/пункты, переопределения,
  свои слоты `extra_n` и пункты `П<n>`). Каталог в коде остаётся источником истины,
  поэтому старые чек-листы читаются без миграции.
- **Ошибки хранилища не показываются «сырыми».** MinIO недоступен → 503 с человеческим
  текстом, PWA кладёт чек-лист в офлайн-очередь и отправит сам; технические детали — в лог.
- **ИИ-провайдер по умолчанию — alem.ai Gemma 4** (модель с картинками; Qwen 3.8/GPT OSS/
  DeepSeek OCR не подходят для проверки фото). Без ключа — честный демо-режим с баннером
  на странице «Чек-листы» и карточкой статуса/проверки ключа в Настройках. Ключи только в
  `infra/.env`.
- **«Кто онлайн».** `users.last_seen` пишется при авторизованном запросе не чаще раза в
  минуту (throttle в зависимости `get_current_user`), онлайн = ≤5 мин, как у устройств.
- **Учётки менторов скриптом** (`scripts/mentors.py`): координатор + водитель + машина +
  виртуальное устройство `WEB-M00N`; пароли печатаются один раз, в базе только хэши;
  `--remove` удаляет комплект вместе с событиями/рейсами в порядке зависимостей.
- **Публичный доступ — Cloudflare Tunnel с ноутбука** (`make tunnel`): два быстрых туннеля
  (панель и API), адреса записываются в `infra/.env` и web пересобирается (NEXT_PUBLIC_*
  вшиваются в бандл). Постоянный хостинг описан в docs/public-demo.md; «всё на Vercel»
  невозможно (нужны backend, PostgreSQL, MinIO).
- **DMS в браузере (PWA «Камера»).** Порт машины состояний устройства на TypeScript
  (`lib/dms`), MediaPipe Face Landmarker в браузере; WASM раздаётся со своего origin
  (`app/mediapipe/wasm`), модель — с Google Storage. События идут в
  `POST /drivers/me/camera-events` под токеном водителя (driver_id из токена, UUID-идемпотентно),
  heartbeat раз в 15 с держит виртуальное устройство онлайн и ставит машину на Live-карту
  по GPS телефона (`ws._live`, состояние процесса: backend — один процесс). Телефон/курение/
  ремень в браузере не считаются (нужен детектор на устройстве). Юнит-тесты правил —
  `npm run test:unit` (раннер Playwright без браузера).
- **Три языка (RU/KZ/EN)** — gettext-подход: `t("русская строка")`, словари `lib/i18n/{kk,en}.ts`
  ключуются исходным русским текстом, отсутствующий перевод → русский. Обёртки расставлены
  AST-кодмодом по JSX-тексту, атрибутам и строкам UI; ключи API/enum (`reason: "устал"`,
  вердикты) не оборачиваются. Смена языка — перезагрузка страницы (строки уровня модуля),
  дерево рендерится после монтирования, чтобы серверный HTML (ru) не расходился с
  клиентским. Плюрализация по языку (`plural`), локаль дат/чисел — `localeTag()`.
  Язык — одна из трёх допустимых записей localStorage (рядом с темой и токеном).
- **Смена языка без перезагрузки** (правка после показа: перезагрузка сбрасывала чек-лист).
  `setLang` уведомляет подписчиков; каждый компонент с `t()` вызывает `useLangVersion()`
  (useSyncExternalStore) и перерисовывается, состояние страниц сохраняется. Константы уровня
  модуля с переводами обёрнуты в `perLang(() => …)` — Proxy, пересчитывающий значение при смене
  языка; zod-схемы форм собираются в компоненте по языку. Тексты из backend (пункты анкеты,
  ракурсы, ИИ-пункты, уроки, причины перерыва) переводятся при отрисовке `t(text)` — словари
  содержат исходные русские строки каталога; свои пункты парка остаются как введены.
- **Карта — OpenStreetMap без ключа.** CARTO basemaps с 2025 года требуют API-ключ (водяной
  знак «API KEY REQUIRED»). По умолчанию тайлы tile.openstreetmap.org, тёмная тема — CSS-фильтр
  `.tiles-dark` (инверсия + поворот оттенка). Свой провайдер с ключом — `NEXT_PUBLIC_MAP_TILES_*`.

## 2026-09-03 — Ревью ШАГ 11 (ручная верификация находок воркфлоу)

Воркфлоу-ревью снова упёрся в лимит сессий (38 из 41 агентов), поэтому находки трёх

- **CSV-инъекция**: ячейка, начинающаяся с `=`, `+`, `-`, `@`, TAB, CR и не являющаяся
  числом, экранируется апострофом (`'`), иначе Excel выполнит её как формулу. Тест

  читаемую 422-строку (как PUT), а не список pydantic.
- **Отчёт**: счётчик событий рейса учитывает только `new/confirmed` (как totals); неделя
  без событий в `score_trend` — `avg_score: null` (не «идеальные 100»); в PDF — заголовки
  «Начало (UTC)», экранирование имени депо в Paragraph, починен fallback пустой таблицы
  типов (приоритет `+` над `or`).
- **Настройки (web)**: состояние вкладки инициализируется из props один раз и ремаунтится

  загрузки настроек не прячет вкладки «Пользователи/Устройства/Внешний вид»; заголовок
