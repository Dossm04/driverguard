# Telegram-бот координатора (ШАГ 12, BOT-1…BOT-4)

Бот присылает координатору критические события с кнопками «Позвонить», «Подтвердить»,
«Ложное», отвечает на `/status` и `/leaderboard`. Работает рядом с backend: раз в 3 секунды
опрашивает `GET /events?status=new`, получателя и типы событий берёт из панели
(Настройки → Уведомления), review делает через `POST /events/{uuid}/review`.

## 1. Создать бота в BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → имя («DriverGuard Alerts»)
   → username, оканчивающийся на `bot`.
2. BotFather выдаст токен вида `1234567890:AAF…` — это `TELEGRAM_BOT_TOKEN`.
3. Если алерты нужны в группе: `/setprivacy` → Disable (иначе бот не видит команды в группе),
   затем добавьте бота в группу.

Токен — только в `infra/.env` (и `backend/.env` для локального запуска). Файлы в `.gitignore`,
в репозиторий не попадают.

## 2. Узнать chat_id и включить алерты в панели

1. Напишите боту `/start` (в личке или в группе). Бот ответит своим описанием и строкой
   `Chat ID этого чата: 123456789` (у группы id отрицательный, вида `-100…`).
2. В панели: Настройки → Уведомления → «Chat ID координатора» → вставьте число → Сохранить.
   Там же отметьте типы событий, о которых слать (по умолчанию: засыпание, телефон, саботаж
   камеры, SOS). Бот перечитывает настройки каждые 15 секунд, перезапуск не нужен.
3. Запасной вариант без панели — `TELEGRAM_CHAT_ID` в `.env` (панель имеет приоритет).
4. Одной командой (найдёт chat_id, запишет в панель, пришлёт тестовое сообщение):
   `cd bot && .venv/bin/python scripts/check_telegram.py --set-chat auto --send-test`
   (токен из `TELEGRAM_BOT_TOKEN` или `--token`, панель — `--api`, по умолчанию localhost:8000).

Команды и кнопки принимаются **только** из этого чата; остальным бот отвечает «Нет доступа»
и показывает их chat_id.

## 3. Запуск

**Docker (рекомендуется):**

```bash
cd infra
docker compose --profile full up -d --build bot
docker compose logs -f bot
```

Служебную учётку бота `bot@driverguard.kz` (роль координатор, пароль `BOT_PASSWORD`,
по умолчанию `bot12345`) создаёт **seed**, а не backend при старте — от её имени идут review
по кнопкам, в аудите видно «Telegram: Имя» нажавшего. Поэтому один раз (и после каждого
обновления ветки, если база засеяна раньше ШАГ 12) выполните на хосте:

```bash
cd backend
.venv/bin/alembic upgrade head      # схема БД
.venv/bin/python -m app.seed        # демо-данные + учётка бота
```

Без этого бот пишет в лог `401: Неверный email или пароль`.

**Локально (без Docker):**

```bash
cd bot && python -m venv .venv && .venv/bin/pip install -e ".[dev]"
set -a; source ../backend/.env; set +a      # TELEGRAM_BOT_TOKEN, BOT_PASSWORD
API_URL=http://localhost:8000/api/v1 .venv/bin/python main.py
```

Переменные: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (запасной), `API_URL`, `BOT_EMAIL`,
`BOT_PASSWORD`, `WEB_URL` (ссылка на панель в сообщении), `TZ` (время в сообщениях,
по умолчанию Asia/Almaty), `BOT_POLL_S` (3), `BOT_SETTINGS_REFRESH_S` (15), `TELEGRAM_API_BASE`.

## 4. Что присылает бот

```
🔴 Засыпание за рулём
👤 Иванов А.С. · KZ 4521 AB
🕒 03.09 14:32 · 84 км/ч
📍 Открыть на карте            ← Google Maps по координатам события
Уверенность 92%
Панель · События
[📞 Позвонить] [✅ Подтвердить] [❌ Ложное]
```

- Алерт уходит, если событие **критическое** и его тип отмечен в панели (BOT-1 + BOT-4).
  Для SOS дополнительно строка «🆘 Причина: …» из контекста события (BOT-2).
- Если у события есть клип — бот прикладывает его видео (при недоступности хранилища —
  только текст).
- «Позвонить» присылает контакт водителя (Telegram не разрешает `tel:`-ссылки в кнопках;
  тап по контакту открывает звонок). «Подтвердить»/«Ложное» меняют статус в backend, кнопки
  исчезают, под сообщением появляется «✅ Подтверждено · Имя · время». «Ложное» возвращает
  водителю баллы Score (правило 5 CLAUDE.md).
- При старте бот не пересылает накопившиеся события (в т.ч. демо-seed) — только новые.
  Если chat_id не задан, критические события ждут и уходят сразу после его указания
  (не старше 24 часов).

`/status` — машины онлайн, события дня (+к вчера), критические за 24 ч, средний Score,
аптайм, список офлайн-устройств. `/leaderboard` — Score водителей за 7 дней с зоной.

## 5. Проверка «Готово, когда»

1. Откройте Swagger `http://localhost:8000/docs` → `POST /api/v1/events` (авторизуйтесь
   как admin) и отправьте:

```json
[{"uuid": "11111111-2222-4333-8444-555555555555", "device_serial": "DG-0001",
  "type": "microsleep", "severity": "critical", "confidence": 0.93,
  "ts": "<текущее время UTC, напр. 2026-09-04T10:15:00Z>", "lat": 51.128, "lon": 71.43, "gps_valid": true,
  "speed_kmh": 84}]
```

2. В течение 10 секунд в Telegram приходит сообщение с кнопками. Метка `ts` должна быть
   свежей: события старше 24 часов бот не пересылает.
3. Нажмите «Ложное» — в панели «События» статус становится «Ложное», в лидерборде Score
   водителя растёт, в аудите — `event_review` от «Telegram-бот» с комментарием «Telegram: Имя».

## 6. Проверка без интернета (фейковый Bot API)

`api.telegram.org` может быть недоступен (корпоративный прокси, CI). Тогда:

```bash
cd bot && .venv/bin/python scripts/fake_telegram.py 8081 &
TELEGRAM_API_BASE=http://localhost:8081 TELEGRAM_BOT_TOKEN=123456:TESTTOKEN .venv/bin/python main.py
curl -s localhost:8081/_sent | python -m json.tool          # что бот «отправил»
curl -s -X POST localhost:8081/_push -d '{"callback": "fp:<uuid>"}'   # нажать «Ложное»
curl -s -X POST localhost:8081/_push -d '{"text": "/status"}'        # команда
```

Фейковый сервер принимает любые вызовы Bot API, отдаёт их списком на `/_sent`
и по `/_push` подкладывает боту нажатие кнопки или команду от чата `777`
(укажите `777` как Chat ID в панели).

## 7. Если сообщений нет

| Симптом | Причина |
|---|---|
| В логе `chat_id не задан — алерт ждёт` | Не заполнен Chat ID в панели и нет `TELEGRAM_CHAT_ID` |
| Событие пришло, алерта нет | Тип не отмечен в Настройках → Уведомления или severity не critical |
| `401: Неверный email или пароль` | В базе нет учётки бота — `python -m app.seed`, либо `BOT_PASSWORD` отличается |
| `Опрос backend не удался` | Backend недоступен по `API_URL` (в Docker — `http://backend:8000/api/v1`) |
| Бот молчит на `/status` | Команда пришла не из чата координатора — сверьте chat_id |
