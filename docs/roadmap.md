# DriverGuard — дорожная карта: что делать дальше и как

Документ для владельца проекта. Для каждого этапа: что нужно, как сделать, какие есть варианты
с плюсами и минусами, что я советую и сколько это займёт. Оценки времени — для одного
разработчика с помощником-ИИ; «дней» = рабочих дней.

Текущее состояние (сентябрь 2026): панель координатора, PWA водителя с камерой в браузере,
Telegram-бот, софт устройства, ML-пайплайн без обученной модели, стенд на 30–40 телефонов через
Cloudflare Tunnel, production-стандарты (логи, метрики, лимиты, бэкапы, CI). Всё работает на
одном ноутбуке в Docker.

---

## Этап 0. Неделя показа жюри (сейчас)

**Что нужно.** Стенд не должен упасть и не должен быть открыт для чужих.

**Как.** По порядку из `docs/demo-jury.md`:

1. `git pull` → `python infra\secrets_check.py --fix` → `docker compose … --profile full up -d --build`.
2. Сменить `admin123` (Настройки → Пользователи) и PIN `1234` (карточки водителей), иначе
   `make tunnel` не откроет ссылку.
3. `make backup` — копия базы «до», `make load-test N=40` — репетиция нагрузки.
4. За час: `make mentors N=40 ROLE=viewer`, `make tunnel`, QR-код на `<панель>/driver`.
5. Репетиция с 2–3 своими телефонами: вход, камера, закрыть глаза, ладонь к уху с «Имитацией 60».

**Совет.** Не запускайте e2e-тесты и `SEED=always` на демо-ноутбуке в день показа — они
стирают базу. Держите второй ноутбук или телефон с 4G как запасной интернет для туннеля.

**Риск.** Бесплатный туннель Cloudflare не гарантирует полосу; если фото чек-листов грузятся
медленно, показывайте чек-лист с одного телефона, а камеру — со всех.

## Этап 1. Сразу после показа (1–2 дня)

- Ротация: ключ alem.ai, токен бота (BotFather → `/revoke`), `JWT_SECRET`, старый утёкший токен
  `8335198469…` отозвать точно.
- Убрать учётки жюри: `scripts/mentors.py --remove`, копия базы `make backup`.
- Записать обратную связь жюри в `docs/decisions.md` (что спрашивали, что не поняли).
- Подкрутить пороги жестов по реальным телефонам: `web/lib/dms/rules.ts` (`PHONE_MS`,
  `SMOKE_REACH`) и `device/dg/config.py`. Сейчас пороги подобраны по геометрии, не по людям.

## Этап 2. Обученный детектор телефон / сигарета / ремень (3–5 недель)

Сейчас телефон и курение ловятся по жестам руки, ремень не ловится вовсе. Это главный
технический долг: без модели устройство «видит» только лицо.

**Что нужно.** Датасет из кабин, обучение YOLOv8n, оценка по стендовому протоколу, экспорт ONNX
и продвижение версии. Пайплайн уже есть: `ml/` (сплит по сессиям, `train.py`, `evaluate.py`,
`export.py`, `registry.py`, Colab-ноутбук).

**Варианты датасета.**

| Вариант | Плюсы | Минусы | Мой совет |
|---|---|---|---|
| А. Свои съёмки в кабинах (5–10 водителей, разное освещение, день/ночь) | Именно ваши ракурсы и камера; лицензия чистая; можно снимать ремень | 2–3 дня съёмок, 3–5 дней разметки (CVAT/Label Studio) | **Основной путь.** 300–500 кадров на класс достаточно для первого детектора |
| Б. Открытые датасеты (State Farm Distracted Driver, DMD, «100-Driver») | Быстро, десятки тысяч кадров | Лицензии часто «только исследования»; ракурс и камера другие; ремня почти нет | Использовать как дополнение для phone/cigarette, не как основу; проверить лицензию перед коммерцией |
| В. Синтетика/аугментация (Albumentations: свет, шум, отражения) | Дёшево, закрывает ночь и блики | Не заменяет реальные кадры | Обязательно поверх А |

**Как.** 1) Снять видео с устройства (`make device-camera`, клипы пишутся сами) → нарезать кадры
`ml/scripts/dataset.py`. 2) Разметить 4 класса: phone, cigarette, seatbelt_on, seatbelt_off.
3) `python scripts/train.py` в Colab (GPU бесплатный, ~1 час на 50 эпох YOLOv8n). 4)
`evaluate.py` → precision/recall по классам; цель ТЗ — precision ≥ 0,9 на стенде.
5) `export.py --check` → ONNX, `registry.py promote v1` → устройство подхватит модель из
`device/models/`. 6) Прогнать стендовый протокол (`docs/bench-protocol.md`).

**Совет.** Начните с двух классов (phone, cigarette): они дают быстрый видимый результат и
проверяют весь пайплайн. Ремень добавьте второй итерацией — там нужен отдельный ракурс
(грудь водителя видна) и ночные кадры.

## Этап 3. Железо: бортовое устройство (4–6 недель, параллельно с этапом 2)

**Что нужно.** Работающий блок в кабине: камера, вычислитель, питание от бортсети, 4G, ночная
съёмка, корпус, крепление.

**Варианты вычислителя.**

| Вариант | Цена | Плюсы | Минусы | Совет |
|---|---|---|---|---|
| Raspberry Pi 5 (8 ГБ) + AI HAT+ (Hailo-8L, 13 TOPS) | ~$130 + $70 | Как в ТЗ; MediaPipe на CPU ~10–15 к/с, YOLO на Hailo ~30 к/с; большое сообщество | Нужна конвертация ONNX → HEF для Hailo (Dataflow Compiler, отдельная работа 3–5 дней); греется, нужен кулер | **Рекомендую** для пилота |
| Raspberry Pi 5 без ускорителя | ~$130 | Проще, софт уже работает | YOLOv8n на CPU ~4–6 к/с — детектор будет считать не каждый кадр (так и задумано в `detector.py`) | Годится для первых 2–3 машин, если Hailo задерживается |
| NVIDIA Jetson Orin Nano | ~$250–300 | Мощнее, CUDA, TensorRT | Дороже, больше ест, сложнее питание | Если планируете 2+ камеры или запись HD |
| Android-телефон в держателе как «устройство» | от $100 | PWA уже работает, есть 4G, GPS, экран, аккумулятор | Перегрев на солнце, водитель может снять, нет управления с сервера, нельзя IR | Как временное решение для пилота «здесь и сейчас» |

**Остальное.** Камера: для ночи — NoIR-камера + ИК-подсветка 850 нм (водитель не видит свет).
Питание: преобразователь 12/24 В → 5 В 5 А с защитой, «зажигание» на GPIO для корректного
выключения. Связь: USB-4G модем (Huawei E3372) или HAT; офлайн-очередь уже есть. Корпус:
печать на 3D-принтере, крепление на стойку А. GPS: USB-модуль (u-blox 7/8).

**Как проверить.** `device/systemd/` — автозапуск; стендовый протокол
(`ml/scripts/bench.py`) — precision/recall и задержка «событие → панель» (цель ≤ 3 с при сети).

**Совет.** Соберите один блок и покатайте его две недели на одной машине до заказа партии.
Половина проблем железа всплывает только в дороге: вибрация, блики, перегрев, отвал USB.

## Этап 4. Сервер и инфраструктура для пилота (1–2 недели)

Сейчас всё на ноутбуке. Для пилота нужен сервер с постоянным адресом.

| Вариант | Плюсы | Минусы | Совет |
|---|---|---|---|
| VPS в Казахстане (PS.kz, hoster.kz, Kcell Cloud), 4 vCPU / 8 ГБ, ~15–25 тыс. ₸/мес | Данные в РК (закон о персональных данных), низкая задержка, просто | Сами администрируете | **Рекомендую** для пилота: `make demo` работает как есть |
| Облако (Yandex Cloud, AWS/GCP) | Управляемые Postgres/S3, масштаб | Дороже, данные за границей — вопросы у заказчика | Когда парков станет несколько |
| Сервер у заказчика (on-prem) | Заказчик спокоен за данные | Доступ для обновлений, бэкапы — на вас | Если заказчик требует |

**Как.** Домен (например `driverguard.kz`) → Cloudflare DNS → именованный туннель
(`cloudflared tunnel create`) или nginx + Let's Encrypt на VPS → `infra/.env`: `NEXT_PUBLIC_*`,
`CORS_ORIGINS`, `MINIO_PUBLIC_ENDPOINT` на домен → `make demo`. Далее: `make backup` по cron с
копией в облачный диск, uptime-kuma на `/api/v1/health/ready`, `LOG_FORMAT=json`.

**Совет.** Начните с VPS и Cloudflare (бесплатный тариф даёт WAF и DDoS-защиту). Kubernetes и
брокеры сообщений не нужны, пока парков меньше пяти — это записано в `docs/ARCHITECTURE.md`.

## Этап 5. Пилот с реальным парком (6–8 недель)

**Что нужно.** 5–10 машин одного парка, 4–6 недель езды, измеримый результат.

**Как.**
1. Договор о пилоте: бесплатно или за себестоимость железа, взамен — данные и отзыв.
2. Юридика: согласие водителей на видеофиксацию (поле `consent_signed_at` уже есть), политика
   хранения (клипы 30 дней — настраивается в Настройках), уведомление профсоюза, если есть.
3. Обучение координатора: 1 час по `docs/demo-script.md`, шпаргалка по review событий.
4. Метрики пилота (из ТЗ, раздел KPI): число микроснов на 1000 км до/после, ложные срабатывания
   (review → false_positive), аптайм устройств, время реакции координатора, средний Score.
5. Еженедельный отчёт заказчику из «Отчёты» (PDF) + разбор ложных срабатываний → очередь
   дообучения (`make retrain-export`).

**Совет.** Выберите парк с длинными ночными рейсами (межгород) — там эффект от контроля
микросна виден за первые две недели. Городская доставка даст больше «отвлечений» и телефонов,
но меньше драматичных случаев.

## Этап 6. Продукт: что доделать в софте (по приоритету)

1. **Push-уведомления координатору** (Web Push) в дополнение к Telegram — 2 дня.
2. **Клипы событий с телефона** (сейчас клипы пишет только устройство): 5-секундный буфер в PWA,
   загрузка по presigned PUT — 3 дня. Даёт «доказательство» и для режима без железа.
3. **Голосовые предупреждения на казахском/русском** на устройстве (сейчас сирена и тон) —
   1–2 дня, готовые фразы через `pyttsx3`/записанные WAV.
4. **Еженедельный отчёт по e-mail** руководителю парка — 2 дня.
5. **Несколько парков в одной панели** (tenant) — 1–2 недели, только когда появится второй
   заказчик.
6. **Приложение из PWA в магазин** (TWA для Google Play) — 2 дня; для iOS PWA ставится с сайта.
7. **Отзыв отдельных токенов, CSP, Swagger только для admin** — из отложенного в
   `ARCHITECTURE.md`, 2–3 дня перед выходом за пределы пилота.

**Совет.** Не делайте пункты 5–7 до пилота: они не влияют на результат пилота, а время
съедают. Пункты 1–3 делайте, если пилот уже согласован.

## Этап 7. Бизнес-часть (параллельно, без кода)

- **Модель оплаты.** Обычно так: железо по себестоимости + подписка за машину в месяц
  (в мире DMS: $15–40/машина/мес). Для РК разумно начать с 5–8 тыс. ₸/машина/мес. Второй вариант
  — «всё включено» в лизинг на 24 месяца. Совет: пилот бесплатный, коммерцию считать с 20+ машин.
- **Конкуренты для сравнения в питче:** Seeing Machines Guardian, Mobileye DMS, китайские MDVR
  с DMS (Streamax, Howen). Ваше отличие: локальные данные, казахский язык, ИИ-чек-лист, цена.
- **Гранты и акселераторы:** Astana Hub (техно-гранты), alem.ai (уже используете), программы
  ЕБРР/Даму для транспортной безопасности. Готовый материал: `docs/DriverGuard_демо_RU.pdf`.
- **Сертификация.** Для установки на транспорт может понадобиться подтверждение электромагнитной
  совместимости блока (ТР ТС 020). Уточните у заказчика заранее — это влияет на выбор корпуса и
  питания.
